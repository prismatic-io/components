This trigger polls the [SAP S/4HANA Cloud OData API](https://api.sap.com/package/SAPS4HANACloud/odata) for new and updated records on a scheduled basis.

#### How It Works

1. The trigger runs on the configured schedule
2. It fetches records from SAP S/4HANA using an OData `$filter` query on the resource's date field (e.g., `LastChangeDateTime ge <sapDateTime>`) to retrieve only records modified since the last poll
3. Records are classified as **created** if their creation timestamp (`CreatedOn` or `CreationDateTime`) exceeds the last poll time; all other returned records are classified as **updated**
4. The trigger updates its internal state after each poll

**Initial sync**

When a **Look-back Date** is set and the trigger has no saved position, its first recurrence is an initial sync. Because a sync seeds a complete starting state, the **Show New Records** and **Show Updated Records** toggles do not narrow it: every record modified on or after the look-back date is returned once, still split into `created` and `updated` as usual.

The sync sends only a lower bound (`<filter field> ge <look-back date at 00:00:00>`) and no upper bound, so a record modified while the sync is running is swept into it. The trigger saves the time the poll ran as its position, and the next scheduled poll resumes from there. All matching records are fetched in the same recurrence, whether or not batching is enabled; batching splits the result into executions but does not spread the fetch over several recurrences. Connection and Resource Type still apply. When no Look-back Date is set, the first recurrence only records its position and returns nothing that existed before it.

**Batching**

Batching is enabled per flow on this trigger: each changed record is dispatched as its own
execution, or grouped by the configured batch size. Batch size and batch concurrency can both be
overridden per instance. Raising concurrency increases the request volume sent to SAP S/4HANA.

To turn it on, select the flow's trigger, open the **Flow control** tab, and switch on **Enable
Batching**. Under **Batch Size**, keep **Trigger default** or choose **Custom batch size**.
**Batch Concurrency** is optional; leave it blank for no batch-level limit.

With batching off, a downstream step reads records from `data.created` and `data.updated`. With batching on, those fields do not exist: each execution receives items shaped `{ "changeType", "record" }` instead. Update any step that reads the older shape before enabling batching. Because batching is enabled per flow, the change applies only to that flow.

#### Returned Data

With batching off, returns an object with two arrays: `created` for new records and `updated` for modified records. Fields shown are representative. The full response object includes additional properties.

#### Notes

- SAP S/4HANA uses OData datetime format internally. The trigger converts ISO timestamps to SAP datetime format before constructing the `$filter` query
- The filter field varies by resource type. `LastChangeDateTime` is used for Change Records and `ChangedOn` for Projects
