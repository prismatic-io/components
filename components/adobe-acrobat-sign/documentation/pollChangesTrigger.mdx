This trigger retrieves existing and ongoing agreements from Adobe Acrobat Sign. Load history once, check for changes on a schedule, or both.

#### How It Works

On each scheduled recurrence, the trigger calls the Adobe Acrobat Sign Search API with a `modifiedDate.range.min` filter set to the last poll time, sorted ascending by `MODIFIED_DATE`. Each returned agreement is classified as **created** when its `createdDate` is after the last poll time, and otherwise as **updated**. The trigger then advances its cursor.

When no cursor exists and no **Look-back Date** is set, the trigger bootstraps with a 24-hour lookback so the API's required `modifiedDate` filter has a valid value.

**Initial sync**

An initial sync seeds a complete starting state rather than a change feed, so inputs that narrow which changes are reported would leave gaps: **Show New Records** and **Show Updated Records** are ignored while it runs, and are the only inputs it ignores. It begins on the first recurrence when the trigger has no stored position and a **Look-back Date** (`YYYY-MM-DD`) is set, and seeds every agreement modified on or after that date exactly once. Left empty, there is no sync and the trigger starts from its first recurrence.

The window has no fixed upper bound, so an agreement modified mid-drain is swept into the sync. With batching off, each recurrence fetches up to 50 pages (5,000 agreements); if more remain it rebases the watermark to the latest modified date it received and continues from offset 0 on the next scheduled recurrence. With batching on, each round fetches one page and the platform drives successive rounds via pagination state until the stream is drained. Once drained, the trigger advances `lastPolledAt` to the wall clock and incremental polling begins from there. Nothing in the payload marks the handoff.

The trigger has no page-size or field-selection input, so nothing else is suppressed.

**Batching**

Batching is enabled per flow on this trigger: each changed record is dispatched as its own execution, or grouped by the configured batch size. Batch size and batch concurrency can both be overridden per instance. Raising concurrency increases the request volume sent to Adobe Acrobat Sign.

To turn it on, select the flow's trigger, open the **Flow control** tab, and switch on **Enable Batching**. Under **Batch Size**, keep **Trigger default** or choose **Custom batch size**. **Batch Concurrency** is optional; leave it blank for no batch-level limit.

With batching off, downstream steps read `results.body.data.created` and `results.body.data.updated`. With batching on, those fields do not exist — each execution receives a single `{ changeType, record }` object. Any step reading the older shape must be updated before batching is enabled. Because batching is enabled per flow, the change is scoped to that flow.

#### Returned Data

The trigger returns an object with two arrays — `created` for new agreements and `updated` for modified agreements. Fields shown are representative. The full response object includes additional properties.
