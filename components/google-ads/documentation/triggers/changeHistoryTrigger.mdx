The Account Change History trigger checks for account modifications with user attribution on a configured schedule. Unlike the New and Updated Campaigns trigger which monitors only campaigns, this trigger captures changes across all resource types using the Google Ads [Change Event API](https://developers.google.com/google-ads/api/docs/change-event).

#### How It Works

1. Run on the configured schedule (e.g., every 15 minutes)
2. Query the change_event resource for modifications since the last poll
3. Return change details including what changed, who made the change, and when
4. Update state with the current timestamp for the next poll

**Batching**

This trigger supports opt-in batching. When batching is enabled on the flow, each change event (or each group of up to the configured batch size) is dispatched as its own execution rather than delivering all changes in a single payload. The default batch size is 50.

Batching splits the executions, not the fetch: the trigger still retrieves the full set of change events in a single poll before any dispatching happens. When batching is enabled, each execution receives one item:

```json
{
  "changeType": "created",
  "record": {
    "changeEvent": {
      "resourceName": "customers/6577008345/changeEvents/1764141874897602~0~1",
      "changeDateTime": "2025-11-26 01:24:34.897602",
      "changeResourceType": "CAMPAIGN_BUDGET",
      "changeResourceName": "customers/6577008345/campaignBudgets/15170398017",
      "clientType": "GOOGLE_ADS_WEB_CLIENT",
      "userEmail": "user@example.com",
      "resourceChangeOperation": "CREATE"
    }
  }
}
```

#### Returned Data

The trigger returns an object containing change events and metadata. When no changes are detected, returns `polledNoChanges: true`.
