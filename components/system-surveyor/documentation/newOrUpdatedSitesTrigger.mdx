The **New and Updated Sites** trigger polls the System Surveyor API for newly created or modified sites on a configured schedule.

#### How It Works

1. The trigger runs on the configured schedule (for example, every 5 minutes)
2. On each run, it queries the System Surveyor API for sites modified after the stored cursor timestamp
3. If new or modified sites are found, the trigger returns them and updates the cursor to the current time
4. If no changes are detected, the trigger reports no changes and updates the cursor

**Initial Sync**

An initial sync seeds a complete starting state. It begins on the first recurrence when the
trigger has no stored position and a **Look-back Date** (`YYYY-MM-DD`) is set, and seeds every site
modified on or after that date exactly once. Left empty, the first recurrence initializes the
cursor and returns no results; polling begins on the second recurrence. The trigger has no filter
inputs, so nothing is suppressed during a sync.

The window has no fixed upper bound, so a site modified mid-drain is swept into the sync. The
position advances to the wall clock captured when the recurrence began, and the first incremental
recurrence resumes from exactly there; nothing in the payload marks the handoff. The trigger fetches
every page before it returns, so the sync finishes in one recurrence whether or not batching is
on.

**Batching**

Batching is enabled per flow on this trigger: each changed record is dispatched as its own
execution, or grouped by the configured batch size. Batch size and batch concurrency can both be
overridden per instance. Raising concurrency increases the request volume sent to System Surveyor.

To turn it on, select the flow's trigger, open the **Flow control** tab, and switch on **Enable
Batching**. Under **Batch Size**, keep **Trigger default** or choose **Custom batch size**.
**Batch Concurrency** is optional; leave it blank for no batch-level limit.

With batching off a downstream step reads `body.data` (an array of site records). With batching on
that field does not exist: each execution receives one `{ "changeType": "modified", "record": ... }`
item, or an array of them when the batch size is greater than 1. Any step reading the older shape
must be updated before batching is enabled. Because batching is enabled per flow, that change is
scoped to the flow rather than to the component or to other flows using the same trigger.

#### Returned Data

The trigger returns an object containing an array of site records that have been created or modified since the previous recurrence. Fields shown are representative. The full response object includes additional properties.
