This trigger retrieves existing and ongoing records for a selected Power BI resource type. Load history once, check for changes on a schedule, or both.

#### How It Works

On each scheduled recurrence, the trigger fetches all records of the selected resource type from the Power BI API. For resource types that expose a creation timestamp, records are classified as **created** when their timestamp is after the last poll time. For resource types without timestamps, the trigger tracks known IDs and reports any new IDs as created.

On the first recurrence for an ID-based resource, the trigger records the current set of IDs and emits nothing. Subsequent recurrences compare against the stored set.

**Initial sync**

An initial sync applies only to **Datasets**, the one resource type that records a creation date (`createdDate`). For **Groups (Workspaces)** and **Reports**, the **Look-back Date** is ignored and the first recurrence records the current IDs as described above. A sync seeds a complete starting state, so **Show New Records**, which would otherwise drop new records from the results, is ignored while it runs; it is the only input ignored. The sync begins on the first recurrence when the trigger has no stored position and a **Look-back Date** (`YYYY-MM-DD`) is set, and returns each dataset created after midnight UTC on that date once. Left empty, there is no sync and the trigger starts from its first recurrence.

The sync covers one full listing of datasets, fetched within the first recurrence whether or not batching is on. The trigger then stores the time that recurrence started as its position, and later recurrences report datasets created after it. No field in the payload marks the handoff.

**Resource Type** still applies. The trigger has no page-size or field-selection input.

**Batching**

Batching is enabled per flow on this trigger: each new record is dispatched as its own execution, or grouped by the configured batch size. Batch size and batch concurrency can both be overridden per instance. Raising concurrency increases the request volume sent to Power BI.

To turn it on, select the flow's trigger, open the **Flow control** tab, and switch on **Enable Batching**. Under **Batch Size**, keep **Trigger default** or choose **Custom batch size**. **Batch Concurrency** is optional; leave it blank for no batch-level limit.

With batching off, downstream steps read `results.body.data.created` and `results.body.data.updated`. With batching on, those fields do not exist. Each execution receives a single `{ changeType, record }` object. Any step reading the older shape must be updated before batching is enabled. Because batching is enabled per flow, the change is scoped to that flow.

#### Returned Data

The trigger returns an object with two arrays: `created` for new records and `updated` (always empty for this trigger). Fields shown are representative. The full response object includes additional properties.
