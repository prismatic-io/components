This trigger polls the [Adobe Analytics API](https://developer.adobe.com/analytics-apis/docs/2.0/) for new records across a selected resource type on a configured schedule.

#### How It Works

1. The trigger runs on the configured schedule (e.g., every 5 minutes)
2. It fetches all records from the selected Adobe Analytics resource, using paginated requests (up to 1,000 records per page) for Report Suites, or a single request to the `/discovery/me` endpoint for Companies
3. Records are compared against the set of previously known IDs; only newly appearing records are captured
4. The trigger updates its internal state after each poll, storing the current set of known IDs

The first recurrence records the IDs that already exist and returns no records; later recurrences report IDs that appear after it. The trigger has no **Look-back Date** input, so existing records are never backfilled.

**Batching**

Batching is enabled per flow on this trigger: each changed record is dispatched as its own execution, or grouped by the configured batch size. Batch size and batch concurrency can both be overridden per instance. Raising concurrency increases the request volume sent to Adobe Analytics.

To turn it on, select the flow's trigger, open the **Flow control** tab, and switch on **Enable Batching**. Under **Batch Size**, keep **Trigger default** or choose **Custom batch size**. **Batch Concurrency** is optional; leave it blank for no batch-level limit.

With batching off a downstream step reads `body.data.created` (`body.data.updated` is always empty). With batching on those fields do not exist: each execution receives one `{ "changeType": "created", "record": ... }` item, or an array of them when the batch size is greater than 1. Any step reading the older shape must be updated before batching is enabled. Because batching is enabled per flow, that change is scoped to the flow rather than to the component or to other flows using the same trigger.

#### Returned Data

With batching off, the trigger returns an object with two arrays: `created` for new records and `updated` for modified records. Because both resource types use ID-based change detection, `updated` is always an empty array. Fields shown are representative. The full response object includes additional properties.

#### Notes

- When **Resource Type** is `Report Suites`, the **Global Company ID** input must be set; requests will fail without it
- ID-based tracking cannot detect updates to existing records; only the appearance of new IDs is reported
