The Drive Subscription trigger automatically creates and manages webhook subscriptions for OneDrive resources throughout the instance lifecycle. Unlike the manual Webhook trigger, this trigger handles all subscription operations automatically, eliminating the need for manual configuration in the Azure portal or Microsoft Graph API.

When the trigger is configured in a flow:
- **On Instance Deploy**: Automatically creates a webhook subscription in Microsoft Graph for the specified OneDrive resource. The subscription points to the instance's unique webhook URL and monitors the configured change types.
- **On Scheduled Execution**: Renews the subscription before it expires, or creates a new one if it has already lapsed. Set a schedule on the trigger to keep notifications flowing.
- **On Lifecycle Notification**: Answers Microsoft Graph's `reauthorizationRequired` challenges by renewing the subscription, and recreates the subscription if Microsoft Graph ever reports it removed.
- **On Instance Deletion**: Automatically removes all webhook subscriptions created by this instance, ensuring clean resource management.

This trigger is ideal for production integrations where webhook lifecycle should be managed automatically alongside the integration instance.

#### How It Works

**Automatic Subscription Creation:**
1. When an instance containing this trigger is deployed, the trigger creates a webhook subscription via the Microsoft Graph API, registering the flow's webhook URL for both change notifications and lifecycle notifications
2. Microsoft Graph validates the webhook endpoint by sending a validation request with a `validationToken` query parameter
3. The trigger responds with the validation token to complete the handshake
4. The subscription becomes active and begins monitoring the specified OneDrive resource

**Notification Processing:**
1. When changes occur to the monitored resource, Microsoft Graph sends webhook notifications to the instance
2. The trigger validates the `clientState` value (if configured) to ensure notifications originate from Microsoft Graph
3. Notifications route to the "Notification" branch for processing
4. The integration uses the notification to trigger delta queries that identify specific changes

**Subscription Renewal:**
1. Microsoft Graph subscriptions expire. Without renewal, notifications stop about 7 days after deployment, or at the configured expiration
2. When the trigger runs on a schedule, it extends the subscription expiration to 10 minutes under the Microsoft Graph maximum for drive resources (42,300 minutes, just under 30 days) and routes the execution to the "Scheduled Renewal" branch
3. If the subscription has already expired, the scheduled run creates a new one
4. Microsoft Graph also sends `reauthorizationRequired` lifecycle notifications to the flow's webhook URL, which the trigger answers by renewing the subscription. Microsoft documents that these notifications do not replace renewal, so the schedule remains the reliable way to keep a subscription active

**Automatic Subscription Cleanup:**
1. When the instance is deleted, the trigger automatically removes all webhook subscriptions
2. This prevents orphaned subscriptions and ensures clean resource management

#### Configuration

**Connection:**
- **OneDrive Connection**: OAuth connection with permission to read the drive being monitored (`Files.Read.All` for OneDrive for Business, `Files.Read` for a personal Microsoft account). Creating the subscription needs no extra permission.

**Subscription Settings:**
- **Resource**: The Microsoft Graph resource path to monitor. Examples:
  - `/me/drive/root` - Current user's root drive folder
  - `/drives/{drive-id}/root` - Specific drive's root folder
  - `/me/drive/items/{item-id}` - Specific folder (personal OneDrive only; OneDrive for Business supports only the root folder)

- **Change Type**: The type of changes to monitor. OneDrive primarily supports `updated` for drive resources.

- **Client State**: Optional validation token sent with each notification. Use to verify notifications originate from Microsoft Graph. The trigger logs a warning if the received clientState doesn't match the expected value.

- **Expiration Date Time**: Optional expiration date/time for the subscription. If not provided, defaults to about 7 days from now. Maximum is just under 30 days (42,300 minutes) for OneDrive resources. Set a schedule on the trigger to renew the subscription before it expires.

<details>
<summary>Lifecycle Events (3)</summary>

| Event | Description |
|-------|-------------|
| `reauthorizationRequired` | Microsoft Graph asks the subscription to be reauthorized, for example before it expires. The trigger renews the subscription. |
| `subscriptionRemoved` | Microsoft Graph removed the subscription. The trigger creates a new one. |
| `missed` | Some change notifications were not delivered. The trigger passes the notice to the flow; run a delta query to catch up. |

</details>

For drive resources Microsoft Graph currently sends only `reauthorizationRequired`; the other two are handled if they arrive. See the [Microsoft Graph change notifications overview](https://learn.microsoft.com/en-us/graph/change-notifications-overview) and the [lifecycle notifications guide](https://learn.microsoft.com/en-us/graph/change-notifications-lifecycle-events).

#### Branches

The trigger uses branching to handle different request types:

- **URL Validation**: Activated during subscription creation when Microsoft Graph validates the webhook endpoint. The trigger automatically responds with the validation token.
- **Notification**: Activated when OneDrive sends change notifications. Process these notifications to identify what changed in the monitored resource.
- **Scheduled Renewal**: Activated when the trigger runs on its configured schedule. The trigger renews the subscription, or creates a new one if none remains. No steps are required on this branch.
- **Lifecycle Event**: Activated when Microsoft Graph posts a lifecycle notification. For drive resources Microsoft Graph currently sends only `reauthorizationRequired`; the trigger also handles `subscriptionRemoved` and `missed` if they arrive. The trigger renews or recreates the subscription as needed and responds with HTTP 202. When Client State is set, a lifecycle notice that carries a different value is still acknowledged with HTTP 202 and reaches this branch, but the trigger does not renew or recreate the subscription for it. A `missed` notice means some change notifications were not delivered; run a delta query to catch up.

#### Best Practices

- **Subscription Renewal**: OneDrive subscriptions expire after about 7 days by default and after just under 30 days (42,300 minutes) at most. Configure the trigger with a schedule (for example, daily) so it renews the subscription before it expires. Each renewal extends the subscription to the 42,300-minute maximum, so any schedule shorter than that keeps it active.
- **Resource Scope**: On personal OneDrive, subscribe to the most specific folder needed, because the root generates more notifications than a single folder. OneDrive for Business supports only the root folder.
- **Client State Validation**: Configure a unique `clientState` value to verify notification authenticity. The trigger logs warnings for mismatched values.
- **Delta Queries**: Webhook notifications indicate changes occurred but don't specify what changed. Implement delta query logic to identify specific changes after receiving notifications.
- **Error Handling**: Monitor logs for subscription creation failures. Common issues include insufficient permissions or invalid resource paths.
- **Multiple Instances**: Each instance creates separate subscriptions. If deploying multiple instances monitoring the same resource, ensure the integration handles duplicate notifications appropriately.

#### Notes

- Subscriptions are automatically created when the instance is deployed and deleted when the instance is removed
- OneDrive only supports `changeType: "updated"` for drive resources
- Personal OneDrive allows subscriptions to any folder; OneDrive for Business only allows root folder subscriptions
- The default expiration is about 7 days; maximum is just under 30 days (42,300 minutes) for OneDrive resources
- The trigger validates `clientState` if configured and logs warnings for mismatches
- Microsoft Graph retries failed webhook deliveries with exponential backoff for up to 4 hours
- The platform automatically URL-decodes query parameters before passing them to the trigger
